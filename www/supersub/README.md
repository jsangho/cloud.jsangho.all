# supersub/ — Super-Sub 목업 데모 (`supersub.jsangho.cloud`)

**팀 프로젝트의 웹(`supersub-ai.com`)을 포트폴리오 앱으로 옮겨 온 사본이다.**
원본은 다른 저장소에 있다 — `super-sub.cloud/www`(Next.js, 소유 백성검).
옮긴 날 2026-10-06, 옮긴 사람 정상호.

🔴 **이것은 포크다. 원본과 자동으로 같아지지 않는다.** 팀이 저쪽을 고쳐도
여기는 그대로이고, 여기를 고쳐도 저쪽에 안 간다. 되돌려 보내야 하는 수정이
생기면 **저쪽 저장소에 직접 내는 것이 맞다.**

## 어디에 무엇이 있나

| 여기 | 원본 |
|---|---|
| `supersub/{components,lib,server}` | `src/{components,lib,server}` |
| `app/(supersub)/s/…` | `src/app/…` (페이지) |
| `app/api/supersub/…` | `src/app/api/…` |
| `public/…`(이름 그대로) | `public/…` — 옮길 때 **이름 충돌 0건**을 확인했다 |

## 옮기며 바꾼 것 — 네 군데뿐이다

**⑴ `@/` 가 가리키는 곳이 다르다.** 원본은 `./src/*`, 포트폴리오는 `./*` 다.
그래서 옮긴 파일의 임포트를 전부 `@/` → `@/supersub/` 로 다시 썼다. 바꾼 것은
임포트 구문 안뿐이고 주석·문자열의 `@/` 는 건드리지 않았다.

**⑵ 한 칸 아래로 내려왔다(`/s`).** 🔴 `/login` 과 `/admin` 을 KAYFABE 가 이미
쓰고 있고, API 는 `/api/auth/*`(NextAuth)·`/api/chat` 이 **정면으로 겹친다.**
그래서 `middleware.ts` 가 `supersub.jsangho.cloud` 로 들어온 것만 `/s/*` ·
`/api/supersub/*` 로 **rewrite** 한다. 리다이렉트가 아니라 rewrite 라
**주소창은 `supersub.jsangho.cloud/home` 으로 남고, 제품 코드의 `href` 를 한 줄도
안 고쳤다.** 대신 `usePathname()` 이 `/s/home` 을 돌려줄 수 있어
`lib/ssPathname.ts` 가 접두사를 뗀다 — 그 비교로 배경 사진·인트로·알약이 켜진다.

**⑶ 루트 레이아웃이 중첩 레이아웃이 됐다.** `app/(supersub)/s/layout.tsx` 는
`<html>`·`<body>` 를 못 그린다(포트폴리오 루트가 이미 그린다). 글꼴 변수와 바깥
배치를 `<div>` 로 내렸다. ✅ **`globals.css`(15,752줄)는 이 세그먼트 아래에서만
실린다** — 포트폴리오·KAYFABE 화면으로 안 샌다.

**⑷ 언제나 목업이다.** `server/backend/index.ts` 가 `mockBackend` 를 **상수로**
돌려준다. 🔴 원본처럼 `USE_MOCK` 환경변수로 두지 않았다 — 빠뜨리면 실서버를
부르는 쪽으로 떨어지기 때문이다. `fastapiBackend.ts`·`fastapiCall.ts` 는
**지웠다**(한 줄로 되살릴 수 있으면 막은 것이 아니다).

## 영상 올리기 — AWS 없이 끝까지 돈다 (2026-10-06)

업로드 두 단계(`/api/videos/upload-url` · `/api/videos`)는 원본에서 게이트웨이를
건너뛰고 FastAPI 를 직접 불렀다 — 🔴 **즉 `USE_MOCK=1` 이던 원본에서도 올리기만은
목업이 아니었다.** 그래서 게이트웨이에 `createVideoUploadUrl` · `registerVideo` 를
**새로 만들어** 목업이 답할 수 있게 했다. 세 단계가 그대로 돈다.

| 단계 | 여기서 일어나는 일 |
|---|---|
| ① 올릴 자리 | `local:<uuid>` 키와 `/api/videos/sink` 를 준다. 🔴 **형식·용량은 진짜로 거른다**(mp4·mov · 200MB) |
| ② 바이트 PUT | `videos/sink` 가 **읽고 버린다**. 서버 메모리에 영상을 안 쌓는다 |
| ③ 등록 | 행을 만든다. 🔴 **60초를 넘으면 반려**하고 사유를 싣는다(반려도 201) |
| 분석 | 상태를 **올린 시각에서 계산한다** — 2초 queued → 20초 running → succeeded. 타이머를 안 쓰므로 인스턴스가 바뀌어도 같은 답이 나온다 |

🔴 **올린 클립은 쿠키에 산다**(`server/mockUploads.ts`). 처음에는 목업의 다른 것들처럼
모듈 변수에 담았는데 **운영에서 올린 영상이 사라졌다** — 등록은 한 서버리스 인스턴스가
받고 그 다음 요청(리포트·재생 주소·목록)은 **다른 인스턴스**로 가서, 그쪽 메모리에는
그 행이 없다(실측: 등록 25초 뒤 리포트가 `VIDEO_NOT_FOUND`). `globalThis` 도 같다.
쿠키는 요청에 실려 모든 인스턴스로 가므로 그 자리를 대신한다 — 한 행에 100바이트가
안 되게 일곱 칸만 배열로 담고 최근 다섯 개까지 들고 있다.

🔴 **두 가지는 진짜가 아니고, 둘 다 화면이 말한다.**

- **분석 결과는 본보기다.** GPU 도 에이전트도 없으므로 누가 무엇을 올려도 같은
  리포트가 간다. 그래서 `summary` 첫 줄에 `[본보기 결과] …` 가 붙는다
  (`mock.ts` 의 `SAMPLE_NOTE`). **지우지 말 것** — 배너에만 적으면 결과 화면까지
  안 따라오고, 그러면 이 수치를 자기 영상을 잰 값으로 읽는다.
- **올린 영상은 이 창에서만 재생된다.** 바이트를 아무 데도 안 남기므로
  `lib/localClips.ts` 가 `blob:` 주소를 들고 있다. 새로고침하면 목록과 분석
  결과는 남고 **재생만** 못 한다. 🔴 그때 **본보기 영상으로 대신 채우지
  않는다** — 내가 올린 것이 아닌 영상이 내 목록에서 재생되면 더 틀린 화면이다.

대기 시간 20초는 **실제보다 짧다**(실측 사용자 시계 약 48초, 2026-09-15). 포트폴리오
데모라 줄였고, 그래서 화면의 단계 표시(`lib/analysisSteps.ts`, 합 51초)보다 먼저
끝나 칸이 건너뛴다. 🔴 **그 표의 숫자는 실측값이라 데모에 맞춰 고치지 않았다.**

## 손대면 안 되는 것

- 🔴 **로그인 화면의 목업 배너**(`components/MockDemoNotice.tsx`) — 「실제
  데이터가 아니다」와 「팀 프로젝트 4명 · 화면 백성검 · 분석 정상호」를 말하는
  유일한 자리다. 개인 도메인에 올라가는 팀 작업이라 이 줄이 없으면 전부 한 사람이
  만든 것으로 읽힌다.
- 🔴 **`server/backend/index.ts` 의 상수 목업** — 위 ⑷.
- 🔴 **`mock.ts` 의 `SAMPLE_NOTE`** — 올린 영상의 결과가 본보기라고 말하는 유일한 자리다.
- 데모 계정은 `server/backend/mock.ts` 의 `DEMO_EMAIL`·`DEMO_PASSWORD` 가 정본이고
  배너가 그 사본을 보여 준다. 한쪽만 고치면 안내가 틀린 값을 가리킨다.
