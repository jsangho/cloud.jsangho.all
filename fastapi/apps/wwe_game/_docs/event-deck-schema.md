# 이벤트 덱 스키마

> **대상:** `apps/wwe_game/domain/constants/cards/*.json`
> **상위 계약:** [`career-simulator-harness.md`](career-simulator-harness.md) §3-D11·D14·D15 · §5
> **작성일:** 2026-08-06

카드 내용은 JSON에, **판정 로직은 코드에** 둔다. JSON은 "무엇이 일어나는가"만 적고, "얼마나 일어나는가"의 최종 계산(굴림·클램프·스타일 가중치)은 `career_rules.py`가 한다.

## 1-2. 반복 억제 — 세 겹으로 막는다

`weekly` 모드는 한 판에 320회를 뽑는다. 카드 수만으로는 §7-8을 통과할 수 없어 세 장치를 겹친다.

| 장치 | 어디에 | 효과 |
|---|---|---|
| **덱 크기** | JSON | 한 판 유효 115장 (once 38~39 + 반복 76~77) |
| **본문 변주** | `bodies` | 반복 카드마다 서로 다른 장면 3개 |
| **쿨다운** | `event_draw.py` | 뽑힌 카드는 이후 N회 후보에서 제외 |

계산: 320회 − once 38 = 282회를 반복 카드 76장이 나눠 가지므로 **카드 반복 3.7회**, 여기에 변주 3개를 곱하면 **문장 반복 1.2회**. §7-8 기준(3회)을 통과한다.

### 쿨다운 규칙 (T5에서 구현)

```
cooldown = max(8, 남은_후보수 // 3)      # 후보가 많을수록 길게
draw_event(run, roll):
    후보 = 조건 통과 카드 − run.recent_events[-cooldown:]
    후보가 비면 → 쿨다운을 절반으로 줄여 재시도 (최대 2회)
    그래도 비면 → 이벤트 없이 진행       # 억지로 띄우지 않는다
```

- `CareerRun.recent_events`에 최근 뽑힌 코드를 **덱 크기만큼만** 보관한다(전체 이력은 `career_log_entries`에 있다).
- **시드 결정성이 깨지지 않는다** — 쿨다운은 후보 목록을 줄일 뿐, 추첨은 여전히 시드 파생 난수다.
- 후보가 비었을 때 쿨다운을 줄이는 이유: 조건이 빡빡한 상태(부상 중 + 특정 액트)에서 후보가 3~4장뿐일 수 있는데, 그때 쿨다운을 고집하면 이벤트가 영영 안 뜬다.

`bodies` 선택도 같은 방식이다 — 직전에 쓴 변주 인덱스를 피해서 고른다.

`event_deck.py`가 일곱 파일을 모두 읽어 `EventCard`로 검증한다. **JSON을 직접 참조하는 코드는 이 로더 하나뿐이다**(§4-13).

## 2. 스탯 — 셋에서 여섯으로

| 키 | 범위 | 시작값 | 뜻 |
|---|---|---|---|
| `popularity` | 0~100 | 10 | 대중 인기도 |
| `inRing` | 0~100 | 20 | 링 기량 |
| `micWork` | 0~100 | 10 | 마이크웍 |
| **`backstage`** | 0~100 | 50 | 백스테이지 평판 — 푸시·기회 배분에 관여 |
| **`alignment`** | −100~+100 | 0 | 성향. 음수는 힐, 양수는 페이스 |
| **`wear`** | 0~100 | 0 | 누적 마모 — 부상 확률과 35세+ 은퇴 압박에 관여 |

여섯 스탯이 **전부 규칙에 읽힌다.** `backstage`는 방출 판정(§3-D24), `alignment`는
인기도 상승 배수(§3-D25)가 소비처다 — 둘 다 한동안 덱에서만 쓰이고 아무 규칙도 읽지
않는 죽은 스탯이었다.

**세 스탯에는 전용 이벤트 풀이 있다**(2026-08-06 사용자 요청) — 인기도·경기력·평판이
각각 12장씩이다. 나머지 셋(마이크웍·성향·마모)은 전용 풀 없이 다른 카드의 부수 효과로만
움직인다.

**화면에 보이는 것은 `popularity`와 `inRing` 둘뿐이다**(2026-08-06 사용자 결정). 나머지
넷은 판정에 관여하되 표시하지 않는다 — 숫자를 여섯 개 늘어놓으면 무엇을 보고 고르는지가
흐려진다. 그래서 **모든 선택지가 이 둘을 반드시 움직이고, 두 값은 서로 다르다**(§7-8·9).

346개 선택지의 분포:

| 조합 | 개수 | 뜻 |
|---|---|---|
| 둘 다 얻음 | 152 | 다만 `wear`·`backstage`·부상 확률로 대가를 치른다 |
| 인기↑ 실력↓ | 109 | 볼거리를 택하고 기예를 미룬다 |
| 실력↑ 인기↓ | 74 | 기예를 택하고 스포트라이트를 포기한다 |
| **둘 다 잃음** | 11 | 발을 뺀 선택 — 대충 하거나 기회를 찬다 |

**뒤의 셋이 이번에 추가됐다.** 근거:

- `backstage` — "선배 갈굼", "각본 반발", "의료진 무단 이탈"의 대가를 받을 그릇이 없으면 이 카드들이 전부 인기도 ±로 뭉개진다.
- `alignment` — 힐/페이스 전환은 프로레슬링 서사의 축이고, 같은 행동이 성향에 따라 정반대로 읽힌다(반칙을 쓰는 힐은 환호받고 페이스는 야유받는다).
- `wear` — §3-D16의 "35세+ 스탯 임계치 미달" 은퇴 조건에 실제 값이 필요하다. 하이플라이어의 "은퇴 시기 단축"이 정확히 이 값이다.

`alignment`는 **잘리지 않고 부호가 뒤집힌다** — 나머지 다섯은 범위에서 클램프된다.

## 3. 액트 — 저장하지 않고 파생한다

새 필드를 만들지 않는다. `(popularity, age)` 에서 순수 함수로 뽑는다.

```
act_of(run):
  popular = popularity >= 60
  4  if age >= (47 if popular else 43)     # 인기도가 황혼을 늦춘다
  3  if popular
  2  if popularity >= 30
  1  otherwise
```

| 액트 | 이름 | 조건 |
|---|---|---|
| 1 | 루키·언더독 | 인기도 < 30 |
| 2 | 미드카드 | 인기도 30~59 |
| 3 | 메인이벤터 | 인기도 60+ 이고 47세 미만 |
| 4 | 황혼 | 43세 이상 (인기도 60+ 면 **47세**부터) |

**나이보다 인기도가 우선한다**(2026-08-06 사용자 결정). 관중이 찾는 선수는 나이로 밀려나지
않는다. 다만 액트 4를 아예 막지는 않는다 — 고별사·횃불·명예의 전당이 거기 있어서, 못 가면
커리어를 끝맺는 카드를 영영 못 본다. **늦출 뿐 없애지 않는다.**

액트는 **내려갈 수도 있다.** 인기도가 떨어지면 3에서 2로 돌아온다 — 대립이 되돌아가는 것(§5)과 같은 이유다. 한 방향으로만 흐르면 모든 판이 같은 모양이 된다.

## 4. 카드 스키마

```jsonc
{
  "code": "act1_veteran_hazing",     // 유일 식별자. 파일 간 중복 금지
  "kind": "main",                    // main | sub
  "arena": "backstage",              // in_ring | backstage | broadcast | public
  "title": "군기",
  "body": "…",                       // once 카드 — 상황 서술 1~2문장
  "bodies": ["…", "…", "…"],         // 반복 카드 — 같은 결정, 다른 장면 3개 (§1-2)
  "weight": 10,                      // 후보 안에서의 추첨 가중치
  "once": true,                      // 한 커리어에 한 번만
  "requires": { … },                 // 아래 §5. 생략한 키는 "무관"
  "choices": [ … ]                   // 아래 §6. 2~3개
}
```

`body`와 `bodies`는 **택일**이다. `once: true`면 `body`(한 번뿐이니 변주가 필요 없다), `once: false`면 `bodies` 3개. 로더가 `bodies or [body]`로 정규화한다.

변주는 **같은 결정을 다른 장면으로** 제시하는 것이다. 원문을 줄여 쓴 것은 변주가 아니다 — 유사도 0.55를 넘으면 §7-9가 잡는다.

`kind`는 서술 톤을 가른다 — `main`은 커리어 분기점이라 로그에 강조되고, `sub`는 한 줄로 흐른다.

`arena`가 `in_ring`이면 **경기 중**이다. 부상 굴림에 링 보정이 붙고, `condition`이 나쁘면 결과가 더 나빠진다.

## 5. `requires` — 생략 = 무관

| 키 | 형태 | 뜻 |
|---|---|---|
| `acts` | `[1,2]` | 이 액트에서만 |
| `minWeek` · `maxWeek` | `int` | 주차 범위 (0~1560) |
| `minAge` · `maxAge` | `int` | 나이 범위 |
| `stats` | `{"popularity":[30,70]}` | 스탯 구간 (양끝 포함) |
| `alignment` | `[-100,-20]` | 성향 구간 |
| `regions` | `["jp","kr"]` | 권역·한국 (§3-D14) |
| `playStyles` | `["high_flyer"]` | 플레이스타일 (§3-D11) |
| `rivalryStage` | `["nemesis"]` | 대립 단계 — 있어야 발동 |
| `conditionGrades` | `["healthy"]` | 부상 등급 |
| `flags` | `["title_shot_booked"]` | 이전 선택이 남긴 표식 |

**모든 조건은 AND다.** 리스트 안은 OR.

## 6. `choices` — 2~3개

```jsonc
{
  "code": "obey",
  "label": "\"알겠습니다, 선배님.\"",
  "risk": "safe",                        // safe | bold | reckless
  "effects": { "backstage": 10, "inRing": 5, "popularity": -5 },
  "injuryRisk": 0.0,                     // 0.0~1.0 추가 부상 굴림
  "heat": 0,                             // 대립 열기 delta
  "flags": []                            // 남길 표식
}
```

- `effects`의 값은 **델타**다. 최종 반영 전에 스타일 가중치·나이 곡선(§3-D10)을 거친다.
- `risk`는 분산을 정한다(§5). `reckless`는 기댓값이 비슷하되 결과가 크게 갈린다.
- `injuryRisk`가 굴려지면 `condition`이 바뀐다. 등급은 `career_rules.py`가 `wear`와 함께 정한다 — **JSON이 부상 등급을 직접 지정하지 않는다.**
- 예외: `"careerEnding": true` 인 선택지는 중대 부상을 확정한다(§3-D16). 액트 4에만 있다.

## 7. 검증 (T5 완료 조건)

1. `code`가 일곱 파일 전체에서 유일하다
2. `requires`의 모든 코드값이 실재한다 (권역·스타일·플래그·대립 단계)
3. 권역·스타일 값마다 전용 카드가 **5장 이상**이다 (§11-7)
4. `flags`를 요구하는 카드는, 그 플래그를 남기는 카드가 반드시 존재한다 (고아 플래그 금지)

   **역방향은 강제하지 않는다.** 남기기만 하고 어떤 카드도 요구하지 않는 플래그가 24개 있다 —
   `turned_heel` · `painkiller_habit` · `push_frozen` · `went_into_business_for_self` 처럼
   **카드가 아니라 `career_rules.py`가 읽는 것**들이다. 성향 전환은 서술 톤을,
   진통제 습관은 부상 굴림을, 푸시 동결은 타이틀 기회 배분을 바꾼다.
   T3·T5에서 이 플래그들을 실제로 읽는 규칙을 붙인다 — 지금은 **기록만 되고 아무 일도 안 일어난다.**

5. 액트 1~4마다 `once` 메인 카드가 **5장 이상**이다
6. `arena: in_ring` 카드가 전체의 **40% 이상**이다 — 링 위 이야기가 중심이다
7. `effects`의 키가 §2의 여섯 개 안에 있다
8. **모든 선택지가 `popularity`와 `inRing`을 둘 다 갖는다** (§2 화면 표시 스탯)
9. **한 선택지 안에서 두 값이 같지 않다** — 같으면 트레이드오프가 사라진다
10. **반복 카드는 `bodies` 3개 이상**, `once` 카드는 `body` 하나 (둘 다 있으면 실패)
11. **한 카드 안의 변주끼리 유사도가 0.55를 넘지 않는다** — 원문 축약은 변주가 아니다
12. 어떤 권역·스타일 조합으로도 **한 판 유효 카드가 110장 이상**이다 (필터 후 기준)
