## 2. 원본 지시서와 이 저장소의 델타 (구현 전 필독)

### D-1. 앱이 존재하지만 **등록되어 있지 않다** *(2026-08-06 부분 해소)*

디렉터리는 있는데 `main.py`·`.importlinter`·`alembic/env.py` 어디에도 없었다. 특히 `.importlinter`에 넣지 않으면 **스포크↔스포크 import를 해도 CI가 안 잡는다** — 계약 밖에 있는 편이 더 위험하다.

**`.importlinter`는 등록 완료**(T1). 나머지 둘은 **지금 할 수 없다**:

| 대상 | 왜 못 하나 | 언제 |
|---|---|---|
| `main.py` | `include_router`할 라우터가 없다 (`career_router.py`는 T10 산출물) | **T10에서 함께** |
| `alembic/env.py` | import할 ORM 모듈이 없다 (`career_orm.py`는 T9 산출물) | **T9에서 함께** |

빈 라우터·빈 ORM을 미리 만들어 등록하는 방법도 있었지만 하지 않았다 — §4-1(요청받지 않은 것 만들지 않기)에 걸리고, 실제로 막는 위험(계약 밖 import)은 `.importlinter` 하나로 이미 사라진다.

### D-1-1. 계약이 **못 보는 디렉터리가 20곳** 있다 (wwe_game 밖의 문제)

T1 검증 중 발견. `__init__.py`가 없어 grimp가 패키지로 인식하지 못하는 디렉터리가 다른 앱에 20곳 있다.

```
apps/kayfabe/app/services      apps/kayfabe/app/dtos
apps/kayfabe/adapter/outbound/repositories · catalog
apps/kayfabe/adapter/inbound/api/schemas
apps/titanic/app/dtos · use_cases          apps/titanic/adapter/inbound/api/schemas
apps/auth/domain/value_objects · services  apps/auth/app/dtos · use_cases
apps/ontology/adapter/outbound · scripts   apps/heyman/adapter/outbound
apps/admin/adapter/outbound/graphs · client · inbound/mcp
apps/lion_king/adapter/outbound
```

**이 안의 모듈로 향하는 import는 계약이 잡지 못한다.** 실제로 처음 위반 프로브를 `kayfabe.app.services.wwe_roster_catalog`로 짰더니 그래프에 그 모듈이 없어 위반이 통과했다 — 계약이 "KEPT"라고 답하는데 실제로는 안 보고 있었다.

**wwe_game은 해당 없다** — 21개 디렉터리 전부 `__init__.py`가 있다.

고치려면 빈 `__init__.py` 20개를 추가하면 되고 부작용은 거의 없지만, **다른 앱을 건드리는 일이라 이 하네스 범위 밖이다**(§4-3 정밀한 수정). 별도 작업으로 올린다.

### D-2. AI 각본 엔진을 쓰지 않는다 — 가장 큰 델타

지시서: *유저 행동에 반응하는 주간 쇼 리포트와 라이벌 반응을 LLM이 실시간 생성*

이 저장소에서 LLM은 이미 돌고 있고(kayfabe 승부예측), **그 운영 실측이 이 결정의 근거다.**

| | LLM 방식 | 규칙 방식 |
|---|---|---|
| 한도 | 모델당 **하루 20회** | 없음 |
| 턴당 응답 | 1~3초 | 즉시 |
| 장애 | 429·503을 2026-08-05 하루에만 여러 번 관측 | 없음 |
| 테스트 | 매번 달라 고정 불가 | 시드 고정으로 완전 검증 |
| 비용 | 유료 전환 압박 | 0 |

**'다음'을 눌러 흘려보내는 게임(§3-D2)에서는 지연이 특히 치명적이다.** 자동 진행이 매 주차마다 1~3초씩 멈추면 그건 자동 진행이 아니다.

그리고 LLM의 유일한 강점이던 *"작성되지 않은 입력에 대응"* 도 이 방식에서는 쓸 자리가 없다 — **선택지가 이벤트 덱에서만 나오므로 플레이어가 만들 수 있는 입력이 유한하고 전부 미리 안다.**

→ 판정도 서술도 전부 규칙으로 만든다(§3-D1·D-3). 포트는 남기되 구현은 규칙 하나뿐이다(§3-D9).

### D-3. "트로피를 플랫폼 순위표와 연동"은 토폴로지를 건드린다

순위표·포인트는 `kayfabe`가 소유한다. `wwe_game`이 그것을 직접 읽거나 쓰면 **스포크↔스포크 위반**이고 `lint-imports`가 차단한다.

→ 초기 범위에서는 **게임이 자기 트로피를 자기 테이블에 보관**하고, 플랫폼 순위표와 엮지 않는다(§3-D7). 연동이 필요해지면 그때 허브(`ontology`)에 공통 프로필 개념을 올리는 별도 작업으로 한다(§13-Q2 결정 완료).

### D-4. "매번 새로운 서사"는 문장 생성이 아니라 상태 설계의 문제다

지시서는 다양성의 출처를 LLM으로 본다. 실제로 이 장르(FM 텍스트 중계, TEW 같은 부킹 게임)가 LLM 없이도 매번 다른 이야기를 만드는 이유는 **대립 관계가 상태를 갖고 전이하기 때문**이다.

```
무관심 → 도발 → 대립 → 배신 → 복수 → 결착
```

라이벌 서넛이 서로 다른 단계에 있고, 자동 진행 중 뽑히는 이벤트가 그 단계를 밀거나 당긴다. 문장을 새로 짓지 않아도 상황 자체가 매번 다르다. **문장은 그 위에 입히는 겉면이다**(§5).

### D-5. "깔끔한 다크 모드 UI"는 이미 정의돼 있다

`www/DESIGN.md`에 브랜드 시스템이 있다 — 캔버스 `#0a0a0c`, 잉크 `#fafafa`, 액션 골드 `#fcbb00`(예측 제출·회원가입 **전용**), Oswald/Pretendard 두 서체, **그림자 없음**, 버튼은 풀 pill.

→ 게임 화면을 새로 디자인하지 않는다. 특히 **골드를 '다음' 버튼에 쓰지 않는다** — 가장 많이 눌리는 버튼에 브랜드 액션 색을 주면 그 색의 의미가 사라진다(DESIGN.md §7).

### D-6. Framer Motion은 이 저장소에 없다

`www/package.json`에 모션 라이브러리가 없다. DESIGN.md §15에 지속시간·이징 토큰이 이미 정의돼 있으므로 **CSS 트랜지션으로 시작한다.** 자동 진행의 로그가 흘러가는 연출도 CSS로 충분하다.

### D-7. "실시간 동기화"는 이 게임에 필요 없다

턴제이고, 상태가 바뀌는 시점은 **'다음'을 누를 때와 이벤트에 답할 때**뿐이다. 요청-응답이면 충분하므로 WebSocket·SSE·폴링을 넣지 않는다.

### D-8. 판정과 서술을 한 덩어리로 쓰면 둘 다 못 고친다

승패 계산과 문장 생성이 섞이면, 밸런스를 고칠 때 문장이 깨지고 문장을 늘릴 때 확률이 흔들린다.

→ **`week_simulation`/`turn_resolution`(무엇이 일어났나)과 `narration`(그것을 어떻게 말하나)을 분리**한다. 판정은 결과 객체를 내고, 서술은 그 결과만 입력으로 받는다.

### D-9. 지시서의 '출신(origin)'은 **국가 + 플레이스타일**로 대체한다

지시서는 *인디 테크니션 · 명문 가문 · 파워하우스 루키* 처럼 출신과 스타일을 한 값에 섞어 놓았다. 섞으면 조합이 고정된다 — "명문가 출신 하이플라이어"를 만들 수 없다.

→ 생성 화면은 **이름(자유 입력) · 성별 · 국가 · 플레이스타일** 네 가지다(§3-D10). 출신 서사는 국가와 스타일의 조합이 대신 만든다.

## 3. 확정된 결정사항 (변경 금지)

### D-1. 판정은 도메인의 순수 함수다
경기 승패·스탯 변동·트로피 획득·대립 전이·이벤트 추첨은 전부 `domain/`이 정한다. 외부 호출이 없다.

### D-2. 진행은 자동, 멈춤은 이벤트에서
플레이어는 **'다음'** 하나로 주차를 흘려보낸다. 시뮬레이터는 주차를 돌리다가 **멈춤 조건**을 만나면 서고, 그때만 선택지를 띄운다.

| 멈춤 조건 | 설명 |
|---|---|
| 랜덤 이벤트 발생 | 이벤트 덱에서 뽑혔다 — **선택 대기 상태**가 된다 |
| PLE 주차 | 큰 경기는 결과를 보여주고 한 번 끊는다 |
| 커리어 종료 | 은퇴·목표 달성 |

**대기 중인 이벤트가 있으면 진행이 막힌다.** 답하기 전에는 다음 주차로 가지 않는다.

### D-3. 서술도 규칙이다 — LLM을 부르지 않는다
템플릿 뱅크 + 슬롯 조합으로 문장을 만든다(§5). 게임 루프에 네트워크 호출이 없다.

### D-4. 난수는 시드로 고정한다
`CareerRun`이 시드를 갖고, 주차 번호와 함께 난수를 파생한다. 같은 세이브를 같은 순서로 진행하면 **결과도 이벤트도 문장도 같아야** 한다. 버그 재현과 테스트가 여기에 달려 있다.

### D-5. 한 번의 진행은 반드시 유한하다
`advance()`는 멈춤 조건을 못 만나도 **최대 주차 수에서 반드시 멈춘다.** 무한 루프는 서버가 멈추는 버그다.

### D-6. 저장은 진행 단위로 한 번
'다음' 한 번 = 주차 N개 시뮬 + 이벤트 추첨 + 로그 적재 + 저장이 한 트랜잭션이다. 중간 상태를 DB에 흘리지 않는다.

### D-7. 플랫폼 포인트·순위표와 엮지 않는다
게임 안에서 완결한다. 트로피는 게임 자기 테이블에 남긴다(§2-D3).

### D-8. 세이브는 로그인 사용자의 것이고, **진행 중인 것은 하나뿐**이다
`users.id` FK로 소유자를 고정한다. 동시에 진행하는 커리어는 1개이며, 새로 시작하려면 기존 커리어를 끝내야 한다(은퇴). 끝난 커리어는 기록으로 남는다.

**구현이 단순해진다** — "현재 세이브"를 찾는 질의가 항상 하나를 돌려주고, 프론트에 세이브 목록·전환 UI가 필요 없다.

**비로그인은 `yearly`(1년)·`quarterly`(분기) 모드만 체험할 수 있다**(2026-08-06 결정, §13-Q3). 두 모드는 틱이 30·120개뿐이라 커리어 전체 상태가 브라우저 로컬 저장에 들어간다. `monthly`·`weekly`는 틱이 390·1560개라 로그만으로도 감당이 안 되므로 로그인을 요구한다.

**도메인은 복제하지 않는다** — 프론트에 규칙 엔진을 두 벌 만들지 않는다. 비로그인 진행은 **상태 없는 엔드포인트**로 처리한다: 클라이언트가 현재 상태를 보내면 서버가 다음 상태를 계산해 돌려주고, 저장은 클라이언트가 한다(§7).

감수하는 것: 상태를 클라이언트가 들고 있으므로 **조작이 가능하다.** 체험판은 플랫폼 순위표와 엮이지 않으므로(§3-D7) 조작해도 잃을 것이 없다고 봤다. 로그인 세이브는 서버가 상태를 들고 있어 이 문제가 없다.

### D-9. 포트는 `ABC`, `NarrationPort` 구현은 하나뿐
`RuleNarrator`만 만든다. LLM 어댑터 자리는 비워 두되 **지금 만들지 않는다.** `HTTPException`은 라우터에서만 만들고, 전용 `AppError` 계층을 만들지 않는다(fastapi/CLAUDE.md).

### D-10. 캐릭터 생성은 네 가지, 시작 나이는 20세 고정

| 항목 | 입력 방식 | 게임에 미치는 영향 |
|---|---|---|
| **이름** | 자유 입력 | 서술의 `{player}` 슬롯. 판정에 영향 없음 |
| **성별** | 선택 (`male` · `female`) | **서술과 타이틀 계열에만 쓴다.** 이벤트 조건으로 쓰지 않는다 |
| **국가** | 선택 | 전용 이벤트 + 서술 슬롯(`{venue}` · `{crowd}`) |
| **플레이스타일** | 선택 | 판정 가중치 + 전용 이벤트 |

**시작 나이는 20세로 고정한다.** 선택지가 아니다 — 나이는 커리어의 시계이지 빌드 요소가 아니다. 52주가 지날 때마다 한 살 오르고, 커리어는 30년(1560주)이므로 **20세에서 50세까지** 간다.

**나이는 판정에 관여한다**(2026-08-06 결정, §13-Q10). 4구간 곡선이며 수치는 `career_rules.py`에 근거 주석과 함께 모은다.

| 구간 | 나이 | 효과 |
|---|---|---|
| 성장기 | 20~25 | 스탯 상승량 ×1.15 |
| 전성기 | 26~34 | 보정 없음 — 타이틀 전쟁 구간 |
| 하락기 | 35~42 | 경기 판정 −4%/년 누적 |
| 베테랑 | 43~50 | 경기 판정 −8%/년 누적, 카리스마(`mic_work`) 보정 + |

은퇴 조건은 §3-D16에 모았다.

### D-10-1. 실존 선수를 바탕으로 내 선수를 만든다 (2026-08-07 사용자 결정)

가명 전환(실존 이름을 창작 이름으로 갈아 끼우는 안)을 두고 나온 결론이다. **이름을 지우는
대신 방향을 바꿨다** — 실존 선수는 라이벌로 남고, 플레이어는 그중 하나를 **바탕으로** 자기
선수를 만든다.

프리셋을 고르면 그 선수의 값이 **기본값으로** 들어오고, 바꾸고 싶은 것만 덮어쓴다.

| 값 | 프리셋이 주는 것 | 사용자가 덮을 수 있나 |
|---|---|---|
| 이름 | **주지 않는다** | 언제나 사용자가 정한다 |
| 성별 · 플레이스타일 | CSV에서 파생 | 예 |
| 국가 | 출생지 → 국가 (목록 밖은 **기타**) | 예 |

**이름만은 물려받지 않는다.** 실존 인물과 같은 이름의 캐릭터를 만들 수 있게 두면 §3-D13의
고지("전개는 허구입니다")가 무의미해진다 — 이름이 같으면 그 사람의 이야기로 읽힌다.
프리셋은 "○○를 바탕으로 만든 다른 선수"까지만 만든다.

프리셋 없이 넷을 직접 정하는 길도 그대로 열려 있고, 빠뜨린 값이 있으면 **무엇이 빠졌는지
짚어서 거절한다.** 임의의 기본값을 채워 주면 사용자가 고르지 않은 값이 조용히 들어간다.

플레이스타일은 **피니셔 이름 → 체중 → 쇼맨** 순으로 읽는다. 기술 이름이 그 선수가 무엇으로
먹고사는지를 가장 잘 드러내고, 120kg 테크니션과 70kg 브롤러가 실제로 있어 체중을 뒤에 둔다.
두 번 어긋나서 고쳤다 — **체중 기준을 디비전마다 따로** 잡았고(75kg 하나로 재니 여성부
32명이 통째로 하이플라이어), 알려진 선수 41명은 **손으로 지정**했다(군터는 서브미션을 쓰지만
그를 정의하는 것은 하드히팅이다).

게임의 권역 다섯 개(§3-D14)에 없는 나라 출신 여섯 명(오스트리아·나이지리아·이스라엘 등)은
**`Country.OTHER`(기타)로 뭉친다**(2026-08-07 사용자 결정). 가까운 나라로 밀어 넣으면
데이터를 조작하는 셈이고, 비워 두면 그 선수를 고를 때마다 국적을 따로 골라야 한다.

**기타는 북미 권역을 쓴다.** 권역은 전용 이벤트가 붙는 자리인데(§11-7 권역당 5장) '기타'라는
묶음에 붙일 고유한 서사가 없다. 전용 서사를 받지 않는 대신 가장 일반적인 풀을 쓰는 셈이고,
무대도 어차피 북미다(§3-D14-1). 나중에 고유한 이야기를 주려면 `Region`을 하나 늘리고
카드를 채우면 된다.

### D-11. 국가와 플레이스타일은 **반드시 이벤트를 갖는다**

선택했는데 아무 일도 안 일어나면 그건 선택이 아니라 장식이다. 이벤트 덱의 조건에 `countries`·`play_styles`를 넣고, **값마다 전용 카드를 최소 5장씩** 만든다(§11-7). 3장이었다가 5장으로 올랐다 — `weekly` 모드가 한 판에 320회를 뽑기 때문이다(§3-D15).

성별은 여기서 빠진다 — 사용자 결정(2026-08-05). 다만 **디비전은 갈린다**(§13-Q9 결정): 성별에 따라 (1) 타이틀·트로피 이름과 (2) **라이벌 풀 필터**가 달라진다. 즉 성별은 *무엇이 일어나는지*(이벤트)가 아니라 *누구를 상대로, 무슨 벨트를 두고* 일어나는지를 정한다.

### D-12. 이름은 값 객체가 검증한다

앞뒤 공백을 자르고 **2~20자**, 제어문자·개행 금지, 공백만으로 이뤄진 이름 금지. 중복은 허용한다(게임 내부 이름이라 유일할 이유가 없다).

검증을 라우터가 아니라 **값 객체**에 두는 이유는, 이름이 서술 템플릿의 슬롯으로 들어가기 때문이다 — 들어오는 입구가 하나여야 한다.

### D-13. 라이벌·챔피언은 **실존 선수 이름**을 쓴다 — 목록은 자체 보관

사용자 결정(2026-08-05). 몰입감을 택했고, 그 대가로 **이름 목록을 이 앱이 따로 갖는다.**

kayfabe에 `app/services/wwe_roster_catalog.py`가 있지만 **import할 수 없다**(스포크↔스포크 금지, §2-D3). 그래서 `domain/constants/roster.py`에 게임용 목록을 둔다.

**베끼는 일은 생성기가 한다** (2026-08-07 개정). `scripts/generate_roster.py`가 kayfabe의 `_docs/wwe_active_roster_cleaned.csv`를 읽어 `roster.py`를 찍어 낸다. 계약이 막는 것은 **런타임 import**이고, 빌드 시점에 파일을 읽어 소스를 생성하는 것은 그 계약과 무관하다. 손으로 적던 때 **58명에서 멈춰 있었고**, 그게 결정이 아니라 미달이라는 것을 사용자가 발견했다(원본은 178명).

CSV가 주지 않는 두 값은 생성기의 상수가 채운다.

| 값 | 조달 |
|---|---|
| 성별 | CSV가 섹션마다 남자→여자 순으로 알파벳을 되감는다. 그 경계를 `FIRST_WOMAN`에 이름으로 박는다. **자동 탐지하지 않는다** — 남자 구간 안에도 순서가 어긋난 이름이 있어("Austin Theory → Tyler Bate") 탐지가 조용히 틀린다 |
| 등급 | NXT 섹션은 통째로 유망주, 메인 로스터는 미드카드, `MAIN_EVENTERS`에 적힌 이름만 정상급 |
| 한국어 표기 | `KOREAN_NAMES` 표. 표에 없으면 영문 그대로 두고 **경고한다** — 조용히 섞이면 화면에서야 발견된다 |

**권역은 담지 않는다** (2026-08-07 사용자 지적). `pool_for()`가 성별·등급만 보므로 어떤 규칙도 읽지 않던 죽은 필드였다. 선수는 어차피 다 미국 무대에 선다 — 무대 권역은 서술이 따로 정한다(§3-D14-1).

감수하는 것:
- **이중 관리** — 로스터가 바뀌면 CSV를 고치고 생성기를 다시 돌린다. 게임은 실시간성이 필요 없으므로 **어긋나도 치명적이지 않다**는 판단이다.
- 목록은 **이름과 최소 속성(성별·대략적 등급)** 만 담는다. 카드·배당 같은 kayfabe 데이터는 복제하지 않는다.
- 이름이 실존 인물이므로 **서술 문구가 사실 주장처럼 읽히지 않게** 한다 — 게임 내 가상 전개임이 화면에 드러나야 한다(§11-17).

고지는 **두 곳에 둔다**(2026-08-06 결정, §13-Q12).

| 위치 | 노출 | 문구 |
|---|---|---|
| 생성 화면 | 시작 전 1회 | 이 게임의 선수명은 실존하지만, 모든 전개·경기·대사는 허구입니다. |
| 커리어 로그 화면 하단 | 상시 | 이 게임의 전개는 가상입니다. |

로그 화면에 상시로 두는 이유: **실존 인물 이름이 실제로 박히는 곳이 로그**이고, 로그는 캡처·공유될 수 있다. 생성 화면 1회만으로는 잘려 나간다.

셋 이상의 앱이 로스터를 필요로 하면 그때 허브로 올린다.

### D-13-1. 명부에 시간 축이 있다 — 30년이면 로스터가 갈린다 (2026-08-07 사용자 지적)

**"30년을 진행하면 기존 선수들이 은퇴할 텐데, 가상 선수를 만들어야 하는 것 아니냐."**

실존 선수의 현재 나이 중앙값은 32세다. NPC 은퇴 나이를 48세로 두면 **30년 뒤 남는 실존
선수가 0명**이다. 오늘의 스냅샷으로 고정하면 로만 레인즈가 일흔에 현역인 세계가 된다.

명부의 각 항목이 네 값을 더 갖는다.

| 값 | 실존 선수 | 가상 선수 |
|---|---|---|
| `debut_week` | 0 (Evolve만 1~4년차) | 1~30년차에 흩뿌림 |
| `retire_week` | **생년월일에서 계산** — `(48 − 나이) × 52`, 최소 3년 | 데뷔 + 24년 |
| `start_tier` | 오늘의 분류 | 유망주, 넷 중 하나는 미드카드 |
| `experience_years` | `나이 − 22` | 0 (미드카드 데뷔는 6) |

**등급은 고정하지 않는다.** 데뷔 6년에 미드카드, 14년에 정상급으로 올라간다(`tier_at`).
고정하면 두 번 틀린다 — 오늘의 NXT 유망주가 서른 해 뒤에도 유망주로 남고, 은퇴로 빠진
정상급 자리를 아무도 채우지 않는다.

**경력은 기다림을 줄이지만 0으로 만들지 않는다**(`MIN_PROMOTION_WEEKS` 4년). 그대로 빼면
14년 차 미드카더가 0주차에 곧바로 정상급이 되어 오늘의 분류를 덮어쓴다 — 실측에서 0년차
남자 정상급이 20명에서 47명으로 부풀었다. 반대로 경력을 아예 안 세면 10년차에 정상급이
5명까지 말랐다(임포트 검증이 잡았다). 둘 사이를 바닥값으로 잡는다.

가상 선수 163명은 이름 조각을 곱해 만들고 실존 이름과 겹치는 조합은 거른다. **손으로 쓰지
않는 이유는 분량이다** — 30년을 채우려면 100명이 넘게 필요하고 뒤로 갈수록 성의가 떨어진다.
조합 순서는 blake2b로 섞는다. 중첩 루프 순서대로 쓰면 "… 크로스"가 연달아 데뷔한다.

**Evolve 13명은 1~4년차 데뷔**로 넣었다(사용자 요청). NXT 아래 육성 단계라 오늘 명부에
넣으면 유망주가 과밀해지고, 이들이 메인 무대에 오르는 건 몇 년 뒤라는 사실과도 어긋난다.

명부가 시간에 따라 변하므로 검증도 바뀌었다 — 임포트 시점에 **0~30년 전 구간**에서 여섯
칸(디비전 × 등급)이 `MIN_POOL` 이상인지 훑는다. 한 시점만 세던 옛 검사로는 20년차에
정상급이 비는 것을 못 본다.

### D-14. 국가는 20개국 이상, **이벤트는 권역 단위로 붙인다**

사용자 결정(2026-08-05): 국가 목록을 20개국 이상으로 연다.

그대로 "값마다 전용 카드"(§3-D11)를 국가에 적용하면 **20개국 × 5장 = 100장**이 지역 카드만으로 나온다. 덱 전체 목표가 100~120장이므로(§3-D15) 스타일·대립·부상 카드를 놓을 자리가 없다. 그래서 이렇게 나눈다.

| 층위 | 쓰임 | 분량 |
|---|---|---|
| **국가**(20+) | 서술 슬롯(`{venue}`·`{crowd}`)과 표시 | 카드 불필요 |
| **권역**(5) | 이벤트 조건 — 북미·유럽·일본·라틴아메리카·오세아니아 | 권역당 5장 이상 |
| **한국**(예외) | 유일한 국가 단위 전용 카드 | 5장 이상 |

국가를 고르면 권역이 자동으로 정해진다. **한국만 국가 단위 전용 카드를 갖는다**(2026-08-05 결정) — 이 플랫폼의 사용자가 만들 캐릭터에 특별함을 주기 위해서다. 지역 카드는 총 **30장**(5권역 + 한국)으로 유지되고, 나머지 70~90장이 스타일·대립·부상·공용 카드 몫이다.

예외를 하나로 제한하는 이유: 국가마다 예외를 늘리면 결국 "국가당 5장"으로 돌아가 §3-D14의 취지가 사라진다.

### D-14-1. 무대는 북미다 — 국적은 선수의 것이지 단체의 것이 아니다 (2026-08-07 사용자 지적)

**서술의 `{venue}`·`{crowd}`는 선수 국적이 아니라 그 주차의 무대 권역에서 나온다.**

처음 구현은 국적의 권역을 그대로 무대로 썼고, 그래서 한국 선수의 30년 커리어가 **전부
한국에서** 열렸다("장충체육관이 조용해졌다"). 단체는 미국에 있고 주간 투어도 미국을 돈다.

| | 비율 | 근거 |
|---|---|---|
| 북미 | 88% (`TOUR_CHANCE` 0.12의 여집합) | 단체의 안방 |
| 해외 투어 | 12% — 연 52주 중 6주쯤 | 0.3까지 올리면 격주로 대륙을 옮겨 투어가 특별하지 않다 |
| 그중 고향 권역 | 40% (`HOMECOMING_SHARE`) | 균등하게 뿌리면 한국 선수가 한국에 서는 일이 30년에 두어 번뿐이라 국적을 고른 의미가 사라진다 |

**국적이 사라지는 게 아니라 자리가 바뀐다.** 이벤트 조건은 그대로 권역을 보고(§3-D14),
국적은 이제 **개선 경기가 언제 오느냐**로 화면에 드러난다. 30년 실측에서 북미 88% ·
고향 7% · 나머지 해외 5%가 나왔다.

북미 출신은 이 가중이 없다 — 그쪽은 매주가 개선 경기다. 그래서 `VENUES[NA]`만 다른
권역의 두 배 넘게(18개) 둔다. 88%를 감당하는 뱅크라 여기가 마르면 전체가 지루해진다.

### D-15. 모드는 4개, **커리어 길이는 네 모드 모두 30년으로 같다**

2026-08-06 결정(§13-Q5). 모드가 정하는 것은 **길이가 아니라 해상도**다 — 얼마나 촘촘히 기록하고 얼마나 자주 개입하느냐.

| 모드 | 1틱 | 틱 수 | 커리어 이벤트 | 평균 간격 |
|---|---|---|---|---|
| `yearly` | 52주 | 30 | **30회** | 1년에 1회 |
| `quarterly` | 13주 | 120 | **80회** | 약 4.5개월에 1회 |
| `monthly` | 4주 | 390 | **160회** | 약 10주에 1회 |
| `weekly` | 1주 | 1560 | **320회** | 약 5주에 1회 |

전부 **1560주 = 30년 = 20세→50세**다(§3-D10).

**`monthly`는 달력의 달이 아니라 4주다.** 달력 달(30.4일)을 쓰면 1560주로 정확히 나뉘지 않아 "52주마다 한 살"(§11-9)이 어긋난다. 내부 시계는 언제나 **주**이고, 모드는 한 틱이 몇 주인지만 정한다. 그래서 틱 수가 360이 아니라 390이다.

**이벤트가 촘촘할수록 덱이 커야 한다.** `weekly`에서 320회를 뽑으므로 덱은 **100~120장**이 필요하다(once 40 + 반복허용 70 안팎). 이 값이 §10-T5의 실제 분량이고, §3-D11의 "값마다 3장"도 함께 올라간다 — 권역·스타일당 **5장 이상**으로 잡아야 균형이 맞는다.

### D-25. 성향은 인기도 상승 배수다

`alignment`도 `backstage`와 똑같이 **죽은 스탯이었다** — 덱에서 129번 쓰이는데 어떤
규칙도 읽지 않아, 힐턴을 하든 페이스로 남든 결과가 같았다.

`인기도 상승 × (1 + |성향|/100 × 0.55)`. **부호가 아니라 절댓값을 본다** — 확실한
악역은 확실한 선역만큼 돈이 된다. 성향 0은 관중이 응원할지 야유할지 모르는 상태이고,
그런 선수는 안 팔린다.

### D-24. 방출 엔딩 — 부진과 다른 실패 (2026-08-06 사용자 요청)

은퇴 조건에 다섯 번째를 더한다. **부진은 관중이 안 찾아서 밀려나는 것이고, 방출은
단체가 못 참아서 잘리는 것이다.** 읽는 스탯부터 다르다.

| | 부진 (`decline`) | 방출 (`released`) |
|---|---|---|
| 읽는 값 | 인기도 · 경기력 · 마모 | **백스테이지 평판** |
| 나이 제한 | 35세 이상 | **없다 — 신인도 잘린다** |
| 유예 | 26주 | **12주** (해고는 갑작스럽다) |
| 면제 | 없음 | **인기도 55 이상이면 면제** |

인기도 면제가 핵심이다 — **돈이 되면 참아준다.** 다루기 힘든 스타는 남고 다루기 힘든
미드카더는 잘린다. 인기도 우선이라는 이 게임의 대전제가 여기에도 걸린다.
`suspension_pending` 같은 플래그를 이미 남겼다면 유예가 절반이 된다.

**이 규칙이 죽은 스탯을 되살린다.** `backstage`는 덱에서 206번 쓰이는데 어떤 규칙도 읽지
않아 모든 커리어가 정확히 50에서 끝나고 있었다. 방출이 그 소비처다.

평판은 세 가지로 움직인다 — 경기에 나오면 오르고(1.8%), **결장하면 깎이고**(11%),
**다칠 때마다 −5**. 그래서 지금은 사실상 "몸이 버티는가" 하나의 축이고, 하이플라이어가
가장 많이 잘린다. T5에서 덱이 붙으면 *처세*라는 두 번째 축이 생긴다.

### D-15-1. 예산의 상한은 덱이다 (2026-08-07 사용자 요청)

**"분기별·월별·주별은 이벤트를 더 늘려도 될 것 같다."** 맞는 지적이었고, 재보니 근거도
나왔다 — `quarterly`는 한 판에서 이벤트가 80회인데 **PLE 정지가 113회**였다. 결정보다
결과 화면을 더 많이 넘기고 있었다.

올리기 전에 두 가지가 먼저 드러났다.

**① 쿨다운이 기억보다 길어서 뒤쪽이 버려지고 있었다.** 쿨다운은 `후보수 // 나눗수`인데
후보가 148장이면 49회이고, 최근 기억(`RECENT_MEMORY`)은 64였다. 나눗수를 올려도 기억을
넘는 만큼은 효과가 없다. 기억을 128로 넓히고 나눗수를 3→2로 낮췄다.

**② §11-19를 이미 넘고 있었다.** 앞선 측정("카드당 3.7회")은 권역×스타일 조합을 전수로
훑은 값이지 한 판이 겪는 분포가 아니다. 진짜 커리어 10판을 돌리자 **같은 카드가 최대 7회**
나왔다(기준 5회). 쿨다운을 고치자 5회로 내려왔다.

그 위에서 예산을 올렸다.

| 모드 | 예산 | 이벤트 간격 | 같은 카드 최다 | 같은 문장 최다 |
|---|---|---|---|---|
| `yearly` | 30 (그대로) | 52주 | 1 | 1 |
| `quarterly` | 80 → **160** | 27 → **10주** | 3 | 3 |
| `monthly` | 160 → **200** | 14 → **8주** | 4 | 3 |
| `weekly` | 320 (그대로) | 5주 | 5 | 4 |

**`weekly`만 올리지 않았다.** 360으로 올리면 같은 카드가 6회가 되어 §11-19를 넘는다.
여기서 상한을 만드는 것은 예산이 아니라 **덱**이다 — 한 커리어가 조건을 통과해 쓸 수 있는
카드가 148장이고 그중 127종이 실제로 등장한다. 더 늘리려면 카드를 더 써야 한다.

**같은 문장 기준(§11-6, 3회 이하)은 `weekly`에서 아직 4회다.** 반복 카드의 본문 변주가
3개뿐이라, 카드가 5회 뜨면 비둘기집으로 어느 변주가 2회는 겹친다. 변주를 5개로 늘리는
콘텐츠 작업이 남았다 — 예산 인상이 만든 문제가 아니라 원래 있던 것이다.

### D-16. 은퇴 조건은 넷이다 — 30년을 다 못 채울 수 있다

2026-08-06 결정(§13-Q10).

| 조건 | 판정 지점 | 성격 |
|---|---|---|
| **50세 도달** (1560주) | `simulate_week()` | 만기 — 항상 도달 가능한 종착점 |
| **플레이어 은퇴 선택** | `DELETE /runs/{id}` | 언제든 스스로 닫는다 |
| **35세+ 스탯 임계치 미달** | `simulate_week()` | 하락기 이후 부진으로 밀려난다 |
| **중대 부상** | `resolve_choice()` | 한 번의 선택으로 커리어가 끝날 수 있다 |

뒤의 둘 때문에 **부상·컨디션 규칙이 새로 필요하다.** `CareerRun`에 `condition`(부상 등급·회복 남은 주차)을 두고, 주차 시뮬이 회복을 진행시킨다. 부상 중에는 경기 판정에 페널티가 붙고, 부상 중 무리하는 선택이 중대 부상으로 번진다.

**감수하는 것:** T3(주차 시뮬)·T5(덱)이 커진다. 부상 회복만 도는 '조용한 주차'가 늘어 서술 다양성(§11-6) 부담도 함께 는다. 그래도 30년을 반드시 완주하는 커리어보다 **끝날 수 있는 커리어**가 매 선택에 무게를 준다고 봤다.

### D-17. '다음' 한 번은 **이벤트를 만날 때까지** 간다

2026-08-06 결정(§13-Q7). 모드가 틱 크기를 정하지만, '다음'이 틱 하나만 진행하는 것은 아니다.

- **기본(`auto`)**: 이벤트·PLE·커리어 종료를 만날 때까지 틱을 이어서 돌린다. `weekly` 모드도 클릭이 1560번이 아니라 이벤트 횟수(320회) 수준으로 줄어든다.
- **토글(`tick`)**: 정확히 한 틱만 진행한다. 촘촘히 보고 싶을 때 쓴다.
- 어느 쪽이든 **상한에서 반드시 멈춘다**(§3-D5). 상한은 틱이 아니라 **주** 기준으로 센다.

`weekly` 모드에서 한 번의 '다음'이 로그 수십 줄을 쌓을 수 있다 — **반복이 가장 잘 드러나는 지점**이라 다양성 기준(§11-6)이 여기서 판가름 난다.

### D-18. 스탯은 셋이 아니라 여섯이다

2026-08-06 결정. 이벤트 덱을 쓰면서 드러난 것 — `popularity`·`in_ring`·`mic_work` 셋으로는 카드 결과의 절반을 표현할 수 없다.

| 추가 | 범위 | 시작 | 없으면 생기는 문제 |
|---|---|---|---|
| `backstage` | 0~100 | 50 | "선배 갈굼"·"각본 반발"·"의료진 무단 이탈"의 대가를 담을 곳이 없어 전부 인기도 ±로 뭉개진다 |
| `alignment` | −100~+100 | 0 | 힐/페이스가 없으면 같은 반칙이 항상 같은 뜻이 된다. 프로레슬링 서사의 축이다 |
| `wear` | 0~100 | 0 | §3-D16의 "35세+ 스탯 임계치 미달"에 읽을 값이 없다. 하이플라이어의 대가가 정확히 이 값이다 |

`wear`는 `WrestlerStats`가 아니라 **`Condition`에 둔다** — 부상 굴림과 함께 움직이는 값이라 부상 등급 옆이 제자리다.

`alignment`만 **음수를 허용한다.** 나머지 다섯은 0~100에서 잘린다.

### D-19. 덱은 JSON, 로더는 하나

카드 내용은 `domain/constants/cards/events_*.json` 일곱 파일에, **판정은 코드에** 둔다. JSON은 "무엇이 일어나는가"만 적고 굴림·클램프·스타일 가중치는 `career_rules.py`가 한다.

스키마와 전체 목록은 [`event-deck-schema.md`](event-deck-schema.md)에 있다. **덱 160장 · 본문 368문장**이며, 한 판에서 살아남는 건 필터를 거쳐 115장이다. **JSON을 읽는 코드는 `event_deck.py` 하나뿐이다**(§4-13).

Python 상수 대신 JSON을 고른 이유: 카드가 160장이고 앞으로 더 는다. 콘텐츠 추가에 코드 리뷰가 필요 없어야 하고, 스키마 검증(§검증 7항목)을 데이터에 직접 걸 수 있다. 대가는 **로더에서 한 번 파싱·검증하는 비용**이며, 모듈 import 시 1회뿐이다.

### D-20. 챔피언십 — 남녀 17벨트와 그랜드슬램 (2026-08-06 사용자 스펙)

**남녀는 벨트 목록 자체가 다르다.** 이름만 다른 게 아니라 **개수와 구조**가 다르다.

| 브랜드 | 1선 | 2선 | 태그 |
|---|---|---|---|
| **스맥다운 (남)** | 언디스퓨티드 WWE | US | WWE 태그팀 |
| **RAW (남)** | 월드 헤비웨이트 | 인터컨티넨탈 | 월드 태그팀 |
| **NXT (남)** | NXT | NXT 노스 아메리칸 | NXT 태그팀 |
| **스맥다운 (여)** | WWE 위민스 | WWE 위민스 US | ↓ |
| **RAW (여)** | 위민스 월드 | WWE 위민스 인터컨티넨탈 | **WWE 위민스 태그팀 (브랜드 통합)** |
| **NXT (여)** | NXT 위민스 | NXT 위민스 노스 아메리칸 | NXT 위민스 태그팀 |

**남성부 9벨트, 여성부 8벨트.** 차이는 태그팀이다 — 남성부는 브랜드별로 둘이지만
**여성부는 통합 벨트가 하나뿐**이라 `TitleSpec.brands`가 `{RAW, SMACKDOWN}`이다.
그래서 벨트의 소속을 단일 `brand`가 아니라 **집합 `brands`** 로 들고 있다.

인기도 임계값(1선 80 · 2선 50 · 태그 30 / NXT 40·25·12)은 남녀 동일하다.

**그랜드슬램은 네 그룹**(월드·인터컨티넨탈·US·태그팀)을 모두 채우는 것이고,
디비전마다 그룹 구성이 다르다. 월드는 두 벨트 중 하나면 되지만 인터컨티넨탈과 US는
각각 필요하다 — **여성부는 태그팀 그룹에도 선택지가 없어 약간 더 빡빡하다**(시뮬에서
그랜드슬램 남 68% 대 여 58%).

`titles_won`을 집합이 아니라 **튜플로 순서대로 쌓는다.** 횟수를 세야 하기 때문이다 —
네 그룹을 각각 두 번씩 채우면 **더블 그랜드슬램**이고, `min(그룹별 획득 횟수)`로
3중·4중까지 확장된다.

**여성부 NXT 계단식 루트**(스펙)는 계층 임계값에서 저절로 나온다 — 인기도 25에
노스 아메리칸이 열리고, 40에 NXT 위민스 챔피언십으로 올라간다.

### D-20-2. 마지막 한 벨트는 확률로 줍는다 (2026-08-07 개정)

"그랜드슬램이 한 그룹 남으면 계층 순서를 덮는다"는 D-20의 규칙을 **보장에서 확률로**
바꿨다(`GRAND_SLAM_CHASE_CHANCE = 0.015`, 타이틀전 한 번당).

**그랜드슬램이 난도가 아니라 생존으로 정해지고 있었다.** 정책만 바꿔 재보니 같은 코드에서
달성률이 0%에서 98%까지 벌어졌다(200판).

| 플레이 | 그랜드슬램 | 채운 그룹 | 커리어 |
|---|---|---|---|
| 안전 (부상 회피) | **98%** | 3.96/4 | 28.4년 |
| 계산적 | 64% | 3.19/4 | 28.0년 |
| 인기도 최대 | 0% | 0.52/4 | 11.9년 |
| 무작위 | 18% | 1.53/4 | 17.2년 |

30년을 완주하기만 하면 이 규칙이 남은 한 벨트까지 데려다줬다. **수치로는 못 잡는다** —
벨트 난도를 +20 해도 안전 플레이는 93%였고, 타이틀전 빈도를 4분의 1로 줄여야 44%가
되는데 그때는 커리어당 대관이 13회에서 4회로 무너져 타이틀 게임 자체가 사라졌다.

내려가는 그림은 D-20의 결정이라 지우지 않고 드물게 만들었다. **회당 확률이 아니라
누적으로 봐야 한다** — 한 그룹만 남은 채로 후반 20~30번의 타이틀전을 치르므로 1.5%도
4분의 1쯤은 결국 걸린다. 0.08만 돼도 계산적 플레이가 46%로 되돌아간다.

**대관 횟수는 그대로다**(커리어당 14.4회). 줄어든 것은 트로피이지 경기가 아니다.

### D-20-1. 챔피언십 — 구버전 (D-20으로 대체됨)

앞서 만든 "계층당 벨트 하나" 구조를 **버렸다.** 실제 WWE는 같은 2선에 인터컨티넨탈과 US가
따로 있고 그랜드슬램은 **둘 다** 요구한다 — 계층 슬롯 하나로는 표현할 수 없다.

| 브랜드 | 1선 | 2선 | 태그 |
|---|---|---|---|
| **스맥다운** | 언디스퓨티드 WWE (인기 80) | US (50) | WWE 태그팀 (30) |
| **RAW** | 월드 헤비웨이트 (80) | 인터컨티넨탈 (50) | 월드 태그팀 (30) |
| **NXT** | NXT (40) | NXT 노스 아메리칸 (25) | NXT 태그팀 (12) |

**그랜드슬램은 네 그룹을 모두 채우는 것이다.** 월드와 태그는 둘 중 하나면 되지만
인터컨티넨탈과 US는 각각 필요하다. 두 벨트가 서로 다른 브랜드에 있으므로
**브랜드를 옮기지 않으면 달성이 불가능하다** — 드래프트가 그 통로다.

`titles_won`을 집합이 아니라 **튜플로 순서대로 쌓는다.** 횟수를 세야 하기 때문이다 —
네 그룹을 각각 두 번씩 채우면 **더블 그랜드슬램**이고, 같은 식으로 3중·4중까지 확장된다.
등급은 `min(그룹별 획득 횟수)`로 구한다.

### D-21. 편성 — PLE는 반드시 경기, 주간은 갈린다 (2026-08-06 스펙)

| 주차 | 비중 | 내용 |
|---|---|---|
| `weekly_show` | 55% | 주간 TV 경기 |
| `promo` | 35% | **경기 없이 대립을 쌓는 주차** |
| `ple` | 7% | 13주마다. **항상 경기가 있다** |
| `off` | 3% | 부상 결장 |

**매주 싸우지 않는다.** 빌드업에 한 주를 쓰면 마이크웍과 대립 열기를 얻고 몸은 쉰다 —
마모도 부상도 없다.

**타이틀전은 PLE가 주무대고 TV에서도 가끔 열린다.** TV 확률은 PLE 한 회의 2%다.
12%로 잡았다가 낮췄는데, **TV 주차가 PLE보다 12배 많아** 총량이 뒤집혔기 때문이다 —
커리어당 TV 22.6회 대 PLE 25.3회로 거의 같아져 PLE가 특별할 이유가 없어졌다.
확률이 아니라 **총량**을 봐야 하는 지점이었다. 지금은 TV 비중 14%다.

### D-21-1. 대회는 달마다 한 번, 12월은 쉰다 — 브랜드마다 따로 (2026-08-07 사용자 요청)

**13주에 한 번은 현실과 너무 멀었다.** 그러면 연 4회이고, 실제 단체는 한 달에 한 번꼴로
큰 대회를 연다. 세 번 고쳐서 지금 모양이 됐고 그 과정이 곧 근거다.

1. **4주 간격 13개** — 균일해서 다루기 쉬웠지만 목록과 안 맞았다
2. **5주 간격 11개** — 목록은 맞았지만 대회 날짜가 해마다 3주씩 밀렸다
3. **달마다 한 번, 12월 제외** ← 지금. 실제 달력과 같다

고정 간격을 버렸다. 달마다 한 번이면 간격이 4~5주로 들쭉날쭉하고, 11월과 이듬해 1월
사이는 **8주가 빈다** — 그게 12월 공백이다. 균일한 간격으로는 만들 수 없다.

| | 메인 로스터 | NXT |
|---|---|---|
| 연 횟수 | **11회** (1~11월) | **4회** |
| 대형 | 로열럼블·레슬매니아·서머슬램·서바이버 시리즈 | 스탠드 앤 딜리버·핼러윈 해벅 |

**NXT는 달력을 따로 쓴다**(사용자 요청). 육성 브랜드라 큰 무대가 드물고 이름도 겹치지
않는다 — 스탠드 앤 딜리버는 그곳의 레슬매니아지 메인의 대회가 아니다. 메인의 열한 번을
그대로 주면 NXT 구간(1.5~3.6년)에만 대회가 서른 번 넘게 열려 정작 올라간 뒤가 심심해진다.

**급이 이 개정을 성립시킨다.** 대회가 2.5배로 늘었는데 전부 진행을 끊으면 클릭이 세 배가
된다. 멈춤은 "보고 싶은 것"일 때만 의미가 있으므로 **대형에서만** 멈춘다 — 실측 클릭은
`weekly` 724 → 726으로 사실상 그대로다.

#### SNME — PLE와 주간 TV 사이 (2026-08-07 사용자 요청)

**분기별 토요일 특별 방송**을 3·6·9·12월 하순에 넣었다. 사용자가 정한 위상이 그대로
설계가 된다 — "PLE와 RAW/스맥다운 사이".

| | 주간 TV | **SNME** | 대회 |
|---|---|---|---|
| 경기 | 62% 확률 | **항상** | 항상 |
| 타이틀전 확률 | 대회의 2% | **대회의 30%** | 100% (대형은 200%) |
| 마모 확률 | 0.03 | **0.10** | 0.18 |
| 진행 정지 | 안 함 | **안 함** | 대형만 |

**주차 종류를 새로 뒀다**(`WeekKind.SPECIAL`). 급으로만 나누면 대회 취급을 받아 마모와
타이틀전이 대회와 같아지는데, 그러면 "사이"가 아니다.

**12월에는 이것만 선다.** 대회는 쉬어도 방송은 돈다 — `QUIET_MONTH` 검사도 대회만 본다.
같은 달에 대회와 함께 서야 하므로 `PleShow.week_offset`을 뒀다(대회는 달 중순, SNME는
2주 뒤). 달만으로 자리를 잡으면 3월에 킹 앤 퀸과 SNME를 같이 둘 수 없다.

**서술은 대회 문구를 쓴다.** 경기가 보장된 밤이고 `{show}`가 이름을 채워 주므로,
"주간 방송 중반 경기"가 아니라 "새터데이 나이트 메인 이벤트에서…"로 읽힌다.

#### 재균형 — 바뀐 것은 달력이지 벨트의 무게가 아니다

대회가 2.5배가 되자 세 지표가 통째로 밀렸다. 같은 시드 60판 기준:

| | 개정 전 | 개정 직후 | 재균형 후 |
|---|---|---|---|
| 커리어당 타이틀전 | 47.3회 | **148.8회** | 42.4회 |
| 그랜드슬램 | 25% | **75%** | 25% |
| 부상 | 7.8회 | 9.5회 | 7.9회 |
| 완주 | 92% | 82% | 93% |

SNME를 더한 뒤에도 유지된다 — 그랜드슬램 30% · 부상 8.2회 · 완주 93%. 특별 방송이
경기 주차를 연 4회 늘리므로 그만큼만 올랐다.

세 값을 내렸다.

- `SHOT_CHANCE` 0.06/0.40 → **0.016/0.108** — 회당 확률을 낮춰 총량을 되돌린다
- `INJURY_PLE_MULTIPLIER` 1.8 → **1.0** — 배수가 붙는 주차가 2.5배가 됐다. 큰 무대의
  위험은 이제 급이 맡는다(`MAJOR_INJURY_MULTIPLIER` 1.25) — 모든 대회가 아니라 **대형이** 위험하다
- `WEAR_GAIN_CHANCE_PLE` 0.50 → **0.18** — 유입이 2.5배가 되자 최고 마모가 100에
  눌어붙어 후반 부상이 몰렸다

#### 부수로 잡은 버그 — 드래프트가 사라지고 있었다

`draft_night`을 **매치 경로에서만** 세우고 있었다. 드래프트 주기(52주)가 옛 PLE 주기(13주)의
배수라 늘 매치 주차와 겹쳐 드러나지 않았는데, 달력이 달 단위가 되자 겹침이 깨졌다 —
드래프트가 프로모·결장 주차에 열리면 **그냥 없던 일이 됐다.** 세 경로 모두에서 세운다.

### D-22. NXT에서 시작해 콜업된다 (2026-08-06 스펙 · **2026-08-07 개정**)

커리어는 `Brand.NXT`에서 출발한다. 콜업 조건은 둘 중 하나 —
**그 주차의 문턱을 넘거나** 또는 **NXT 벨트 3종 석권**. 어느 쪽이든 **1.5년(78주)
하한**을 먼저 채워야 한다.

**문턱은 고정값이 아니라 재적 기간의 함수다** — 1.5년에 76, 5년에 30까지 선형으로
내려가고 그 뒤로는 멈춘다. 고정값 하나(구 48)로 두면 커리어가 전부 같은 인기도에서
같은 시기에 올라가 NXT 구간이 판마다 똑같아진다. 내려가는 문턱은 같은 규칙 하나로
**스타와 저니맨을 가른다** — 빨리 큰 선수는 일찍 올라가되 높은 인기도를 들고 가고,
더디 큰 선수는 늦게 올라가되 바닥에서 다시 시작한다.

콜업하면 **인기도가 0.42배로 깎인다.** 그대로 가져오면 즉시 메인 로스터 상위 임계값에
서서 큰 물 커리어가 통째로 사라진다. NXT 벨트는 반납하되 획득 이력은 남는다.

**개정 이유 — 문서의 6.0년차는 덱 이전 수치였다.** T4·T5로 이벤트가 실제로 뜨기
시작하자 NXT 구간이 80주로 줄어 **콜업이 평균 1.6년차 · 최단 0.5년**이 됐다(200판
실측). 아래 "NXT 2.4배" 항목의 근거는 **이제 사실상 죽은 값이다** — 배수를 2.4에서
0.6까지 낮춰도 콜업 시기가 1.6→1.8년으로만 움직인다. 인기도의 출처가 주차 성장에서
이벤트로 넘어갔기 때문이다. 그래서 배수가 아니라 **문턱과 하한**으로 구간을 잡았다.

NXT에서는 **인기도가 2.4배 빨리 오른다** — 작은 물에서는 빨리 눈에 띈다. 덱이 없던
시절에는 이 배수가 유일한 가속기였다(없으면 콜업까지 평균 21.5년, 41%는 끝내 못
올라감). 지금은 이벤트가 그 자리를 대신하므로 **기울기에 거의 기여하지 않는다.**

### D-22-1. 깜짝 콜업 — 부상 공백을 메우러 올라간다 (2026-08-07 사용자 요청)

메인 로스터에 자리가 비면 **준비가 덜 된 선수를 부른다.** 정상 경로와 세 가지가 다르다.

| | 실력 콜업 | 깜짝 콜업 |
|---|---|---|
| 계기 | 문턱 도달 | **이벤트 카드에서 수락** |
| 하한 | 1.5년 | **없음**(카드가 `minWeek: 26`) — 그게 '깜짝'인 이유 |
| 남는 인기도 | 0.42배 | **0.63배** — 대타 출전 자체가 생중계 화제라 무대가 스포트라이트를 켜 준다 |

**규칙이 아니라 선택이다.** 자동 발동으로 두면 플레이어에게는 그냥 사고이므로, 카드
3장(`events_callup.json`)에 수락/거절을 붙였다. 거절도 손해가 아니다 — NXT에 남아
기량을 다듬는 쪽이 문턱을 더 빨리 넘길 수도 있다.

**카드는 브랜드를 직접 바꾸지 않는다.** 수락 선택지가 `callup_emergency` 플래그만
남기고, 다음 활동 주차에 `week_simulation`이 그걸 읽어 콜업을 실행한다. 덱 데이터가
소속 규칙을 알게 되면 "콘텐츠 추가에 코드 리뷰가 필요 없다"는 §3-D19의 전제가 깨진다.
이를 위해 `requires.brands`를 스키마에 추가했다 — NXT 밖에서는 카드가 뜨지 않는다.

**결장 주차에는 발동하지 않는다.** 부상자는 대타로도 못 나간다. 플래그는 남으므로
복귀하는 주에 올라간다 — 자리가 그때까지 비어 있는 셈이라는 점은 감수한 단순화다.

### D-23. 인기도 ↔ 챔피언십의 되먹임 고리

세 규칙이 하나의 고리를 이룬다.

1. **인기도가 기회를 만든다** — PLE당 타이틀전 확률 = `0.06 + 0.40 × 인기도/100`
2. **기회가 벨트를 만든다** — 닿는 가장 높은 벨트가 상대. 그랜드슬램 한 그룹 남으면 우선
3. **벨트가 인기도를 지킨다** — 보유 중 망각이 느려진다(월드 ×0.25 · 2선 ×0.55 · 태그 ×0.75)

3번이 없으면 고리가 안 닫힌다. 대관 순간에만 인기도를 주고 식게 두었더니 인기도가
평균 63에서 멈춰 월드 임계값(80)에 닿는 판이 200 중 12뿐이었고 **그랜드슬램이 2%로 죽었다.**

**방어는 새 대관이 아니다.** 처음엔 방어 승리에도 획득 처리를 해서 월드 벨트를 커리어당
11.2회 "딴" 것으로 집계됐다. 한 번 감고 서른 번 지킨 것과 서른 번 새로 감은 것은 다르다.

## 4. 금지사항

위반하는 코드는 작성 즉시 폐기 대상이다.

1. **게임 루프에서 네트워크 호출** (LLM·외부 API 무엇이든) — §3-D3
2. `advance()`가 멈춤 조건에만 의존 — 상한 없는 루프 금지 (§3-D5)
3. 대기 중인 이벤트를 무시하고 다음 주차 진행 (§3-D2)
4. `wwe_game`이 `kayfabe`·`soccer` 등 다른 스포크를 import (허브 경유만 허용)
5. `ontology`가 `wwe_game`을 import
6. `domain/`에서 `sqlalchemy`·`fastapi`·`httpx` import
7. 도메인·포트에서 `HTTPException` 발생
8. 시드 없는 `random` 사용 — 재현 불가능해진다 (§3-D4)
9. 판정 코드 안에서 문장을 만들기 (§2-D8)
10. 새 게임 엔진·상태 관리 라이브러리 도입 (Redux·XState·게임 프레임워크 등)
11. WebSocket·SSE·폴링 도입 (§2-D7)
12. 골드(`#fcbb00`)를 '다음' 버튼 등 일반 조작에 사용 (DESIGN.md §7)
13. 이벤트 문구·템플릿 문자열을 코드 곳곳에 흩기 — 덱과 템플릿은 각각 한곳에 모은다
14. **성별을 이벤트 조건에 넣기** (§3-D11) — 서술·타이틀 이름에만 쓴다
15. 시작 나이를 20세 외의 값으로 만들기 (§3-D10)
16. **모드에 따라 커리어 길이를 다르게 만들기** — 네 모드 전부 1560주다 (§3-D15)
17. 내부 시계를 주(week)가 아닌 단위로 두기 — 틱은 주에서 파생될 뿐이다 (§3-D15)
18. **프론트에 판정·이벤트 규칙을 복제하기** — 비로그인 체험판도 서버가 계산한다 (§3-D8)
19. 비로그인에 `monthly`·`weekly` 모드를 열어 주기 (§3-D8)

### 진행 루프 (순수 함수, §3-D2)

```
advance(run, step, max_weeks) -> AdvanceResult      # step: auto | tick  (§3-D17)
  반복:
    week_report = simulate_week(run, roll)      # 자동 시뮬 — 회복·나이·부진 판정 포함
    event       = draw_event(run, roll)          # 조건 통과 카드 중 가중치 추첨
    if event: 멈춘다 (pending_event 설정)
    if PLE 주차 or 종료 조건: 멈춘다             # 50세·부진·부상 (§3-D16)
    if step == tick and 진행한 주차 == mode.weeks_per_tick: 멈춘다
    if 진행한 주차 == max_weeks: 멈춘다          # §3-D5
  -> (week_reports[], stop_reason, pending_event | None)
```

- `stop_reason`은 화면이 무엇을 보여줄지 정한다: `event` · `ple` · `ended` · `tick` · `max_weeks` · `ready`. **구현에서 이름이 조금 짧아졌고 `ready`가 늘었다** — 시작·조회처럼 진행하지 않은 응답을 "한 틱 갔다"와 같은 값으로 두면 프론트가 둘을 구분하지 못한다.
- **모드는 해상도를 정한다** — 커리어 길이는 네 모드 모두 1560주로 같고, 다른 것은 틱 크기와 이벤트 예산뿐이다(§3-D15).
- **이벤트 밀도는 예산에서 파생한다** — 남은 주차와 남은 `event_budget`으로 매 주차 추첨 확률을 정한다. 초반에 몰아 쓰고 후반이 조용해지는 일이 없도록, 확률은 `남은예산 / 남은주차`로 매 주차 다시 계산한다.
- `max_weeks`는 **주** 단위 안전 상한이다(§3-D5). 틱이 아니라 주로 세는 이유는 `yearly` 모드의 한 틱이 이미 52주이기 때문이다 — 틱으로 상한을 걸면 모드마다 상한의 의미가 달라진다.

### 이벤트 추첨 (순수 함수)

- 조건(`requires`)을 통과한 카드만 후보다 — 주차·스탯·대립 단계·`once` 여부.
- 후보 중 가중치 추첨. **시드 파생이므로 같은 세이브는 같은 이벤트를 같은 주차에 만난다.**
- 후보가 없으면 이벤트 없이 계속 진행한다. 억지로 띄우지 않는다.

### 판정·대립 전이 (순수 함수)

- **플레이스타일은 판정 가중치다** — 테크니션은 `in_ring` 기여가 크고 부상이 적으며, 파워하우스는 강자 상대 보정이 붙고, 하이플라이어는 분산과 부상 위험이 크며, 브롤러는 대립 `heat`를 잘 올리고, 쇼맨은 `mic_work`·인기 기여가 크다. **수치는 `career_rules.py`에 근거 주석과 함께 모은다.**
- `resolve_choice(run, event, choice, roll) -> TurnOutcome`. `risk`가 높을수록 분산이 크고 기댓값은 비슷하다.
- `advance_rivalry(rivalry, outcome, roll) -> Rivalry`. **되돌아가기도 있다** — 무시하면 `heat`가 식어 `indifferent`로 내려간다. 한 방향으로만 흐르면 모든 판이 같은 모양이 된다.
- 스탯은 0~100에서 잘린다. 음수·초과는 값 객체가 막는다.

### 서술 생성 (순수 함수, §3-D3)

```
템플릿 뱅크: (WeekKind · OutcomeKind · 스탯 구간) → 문장 템플릿 목록
슬롯:        {player} · {rival} · {crowd} · {move} · {venue} · {reaction}
             {venue}·{crowd}는 **국가**에서, {move}는 **플레이스타일**에서,
             {rival}은 **로스터 목록**(§3-D13)에서 고른다
선택:        시드에서 파생된 인덱스 (같은 세이브 = 같은 문장)
```

자동 진행은 **주차마다 한 줄**을 만든다. 한 번의 '다음'이 여러 줄을 쌓으므로 반복이 더 잘 보인다 — 다양성은 측정 가능한 목표로 둔다(§11-6).

## 7. API 계약 (prefix `/api/career`)

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| POST | `/runs` | 필요 | 새 커리어 시작 (이름·성별·국가·스타일·모드) |
| GET | `/runs/current` | 필요 | 세이브 + 대기 중 이벤트(있으면) |
| POST | `/runs/{run_id}/advance` | 필요 | **'다음'** — 주차 시뮬 후 멈춘 지점까지 반환 |
| POST | `/runs/{run_id}/choices` | 필요 | 대기 중 이벤트에 답한다 → 판정·저장 |
| GET | `/runs/{run_id}/log` | 필요 | 커리어 로그 (페이지네이션) |
| DELETE | `/runs/{run_id}` | 필요 | 은퇴 — `end_reason: player` 로 닫는다 (§3-D16) |
| GET | `/modes` | 불필요 | 모드 4종 메타 (틱 크기·비로그인 허용 여부) |
| POST | `/guest/runs` | 불필요 | 체험판 시작 — 저장하지 않고 초기 상태를 돌려준다 |
| POST | `/guest/advance` | 불필요 | 체험판 '다음' — 상태를 받아 다음 상태를 돌려준다 |
| POST | `/guest/choices` | 불필요 | 체험판 선택 판정 — 상태를 받아 다음 상태를 돌려준다 |

`POST /runs` 본문:

```json
{ "name": "장상호", "gender": "male", "country": "KR",
  "playStyle": "technician", "mode": "quarterly" }
```

- 나이는 받지 않는다 — **20세 고정**이다(§3-D10).
- 모드는 `yearly` · `quarterly` · `monthly` · `weekly` 넷뿐이다(§3-D15).
- 이름 검증 실패는 400이고, 문구는 무엇이 잘못됐는지 알려준다("2~20자로 입력해 주세요").

`advance` 본문:

```json
{ "step": "auto" }
```

- `auto`(기본) = 이벤트를 만날 때까지, `tick` = 정확히 한 틱만 (§3-D17).

### `/guest/*` — 비로그인 체험판 (§3-D8)

**상태를 서버에 저장하지 않는다.** 클라이언트가 세이브 전체를 본문에 담아 보내면, 서버가 규칙을 돌려 다음 상태를 통째로 돌려준다. 저장은 브라우저가 한다.

```json
// POST /guest/advance
{ "run": { …CareerRun 전체… }, "step": "auto" }
```

- **`yearly`·`quarterly` 외의 모드는 400으로 거절한다**(§3-D8). 모드 메타의 `guestAllowed`가 판정 근거다.
- 라우터는 받은 `run`을 도메인 값 객체로 되돌리며 검증한다 — 범위를 벗어난 스탯·모르는 코드·1560 초과 주차는 400이다. **신뢰하지 않되, 막지도 않는다**: 규칙에 맞는 값이면 그대로 받는다(조작 감수, §3-D8).
- 응답 모양은 로그인 쪽 `advance`와 같되 `run`에 전체 상태가 들어간다.
- 유스케이스는 **하나를 공유한다.** 다른 것은 "상태를 어디서 읽고 어디에 쓰는가"뿐이므로, 리포지토리 대신 메모리 상태를 쓰는 어댑터를 끼운다.

`advance` 응답 모양:

```json
{
  "weekReports": [ { "week": 12, "kind": "weekly_show", "narration": "..." } ],
  "stopReason": "event",
  "pendingEvent": { "code": "backstage_ambush", "title": "...", "body": "...",
                    "choices": [ { "code": "strike_back", "label": "맞선다" } ] },
  "run": { "week": 14, "stats": { "popularity": 41 } }
}
```

- 응답은 camelCase(`response_model_by_alias=True`) — 기존 라우터와 같다.
- **본인 세이브만 접근**한다. 남의 `run_id`는 404로 답한다(존재 여부를 알려주지 않는다).
- 내부 확률·주사위 값·가중치는 응답에 넣지 않는다.

## 8. 예외 → HTTP 상태 코드 매핑

| 상황 | 발생 지점 | 예외 | 상태 | 사용자 문구 |
|---|---|---|---|---|
| 세이브 없음·남의 것 | 리포지토리 | `RunNotFoundError` | 404 | 커리어를 찾을 수 없습니다. |

| 대기 이벤트가 있는데 진행 시도 | 유스케이스 | `ChoiceRequiredError` | 409 | 먼저 선택을 마쳐야 합니다. |
| 대기 이벤트가 없는데 선택 제출 | 유스케이스 | `NoPendingEventError` | 409 | 선택할 이벤트가 없습니다. |

## 11. 검증 기준 (Definition of Done)

1. **'다음'만 눌러도 커리어가 끝까지 진행된다** (선택 없이도 막히지 않는다)
2. **대기 중인 이벤트가 있으면 진행이 409로 막힌다**
3. `advance()`가 멈춤 조건을 못 만나도 최대 주차에서 반드시 멈춘다 (§3-D5)
4. 같은 시드·같은 선택 순서 → 같은 결과·같은 이벤트·같은 문장
5. 조건 미달 이벤트가 뽑히지 않고, `once` 카드가 한 판에 두 번 안 나온다
6. **다양성**: 같은 주차 유형을 30주 반복해도 같은 문장이 3회를 넘지 않는다. **이벤트 본문도 같은 기준을 받는다** — `weekly` 한 판(320회)에서 같은 문장이 3회를 넘지 않는다(현재 최악 조합 1.2회)
7. **권역·플레이스타일 값마다 전용 이벤트가 5장 이상**이고, 다른 값으로는 뽑히지 않는다 (§3-D11·D14·D15)
8. 성별이 이벤트 조건 어디에도 쓰이지 않는다 (코드 검색으로 확인)
9. 나이가 시작 20세에서 52주마다 정확히 1씩 오르고, 1560주에 정확히 50세다
10. 이름은 2~20자 밖·제어문자·공백만이면 저장되지 않는다
11. 대립이 단계를 오르내린다 — 무시하면 식고, 밀면 격해진다
12. 남의 `run_id`로 접근 시 404 (존재 여부 노출 없음)
13. 게임 루프에 네트워크 호출이 0회다 (코드 검색으로 확인)
14. 응답 어디에도 내부 확률·주사위 값이 없다
15. `lint-imports` 계약 KEPT — wwe_game이 다른 스포크를 import하지 않는다
16. 모든 국가가 권역에 매핑돼 있고, 매핑 없는 국가를 고를 수 없다 (§3-D14)
17. **고지가 두 곳에 있다** — 생성 화면 1회 + 커리어 로그 화면 하단 상시 (§3-D13)
18. **네 모드 전부 1560주에서 끝난다** — 틱 수만 30·120·390·1560으로 다르다 (§3-D15)
19. **덱이 100장 이상**이고, `weekly` 한 판(320회 추첨)에서 같은 카드가 5회를 넘지 않는다 (§3-D15)
20. **이벤트 예산이 고르게 소진된다** — 커리어를 4등분했을 때 각 구간 이벤트 수가 예산의 20~30%다 (§5)
21. **은퇴 4조건이 각각 실제로 발생한다** — 50세 만기·플레이어 선택·35세+ 부진·중대 부상 (§3-D16)
22. 부상 중에는 판정 페널티가 붙고, `weeks_left`가 0이 되면 정확히 회복된다 (§3-D16)
23. `step: tick`이 정확히 `weeks_per_tick` 주만 진행한다 (이벤트를 만나면 그 전에 멈춘다) (§3-D17)
24. **`/guest/*`가 `monthly`·`weekly`를 400으로 거절한다** (§3-D8)
25. 체험판과 로그인 플레이가 **같은 유스케이스**를 쓴다 — 판정 규칙이 한 곳에만 있다 (§4-18)
26. 조작된 체험판 상태(범위 밖 스탯·1560 초과 주차)가 400으로 걸린다
27. §12 게이트 전부 통과
